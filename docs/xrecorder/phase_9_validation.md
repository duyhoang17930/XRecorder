# Phase 9 — Export queue and media tools

Implemented atomic export-job snapshots, native progress, cancellation, retry and interruption recovery. Jobs survive Activity recreation through an application-scoped queue. Keep the app open: this version does not promise background execution. Process loss marks unfinished jobs failed for explicit retry. Pending MediaStore URIs are journaled; recovery only deletes pending rows owned by this package, and recognizes already-published rows. Final publication cannot be cancelled. Sources and drafts are never rewritten.

The shared preview/export composition supports speed 0.5–2×, original audio gain 0–2×, pitch, text overlay, grayscale/invert, black aspect-ratio padding, output height and target variable FPS. SAF-selected audio is mixed as a looping music track with separate gain. Pitch affects all original clip audio, not isolated speech. Smaller output dimensions offer compression without a guaranteed final size. Photo crop/annotation remains in P6. GIF export renders the composition first, then writes an original GIF89a/RGB332 encoder: maximum 15 seconds, 320 px longest edge, 10 FPS, no audio. No bundled FFmpeg or encoder license dependency was added.

API 36 emulator integration passed on 2026-11-04: persisted project, real native preview, transformed MP4, queued cancellation, retry/cancel, speed/volume/pitch/text/filter/music composition and GIF publication. Independent inspection: H.264 1068×480 / 1.500000 s, AAC starts 0.010204 s / 1.513923 s. GIF 320×144, 15 frames / 1.5 seconds. Both decode with desktop FFmpeg; MP4 verification preserves the demux time base to avoid null-output timestamp rounding warnings. Host split tests now account for project speed and confirm effect persistence. Visual inspection caught black default overlay text, corrected to white with a dark background. Remux preserves display rotation and static video tails.

Primary API references: [Transformer progress/cancel](https://developer.android.com/media/media3/transformer/getting-started), [speed](https://developer.android.com/reference/androidx/media3/transformer/EditedMediaItem.Builder), [audio gain](https://developer.android.com/reference/androidx/media3/common/audio/ChannelMixingAudioProcessor), [pitch](https://developer.android.com/reference/androidx/media3/common/audio/SonicAudioProcessor), [text](https://developer.android.com/reference/androidx/media3/effect/TextOverlay), [background](https://developer.android.com/reference/androidx/media3/effect/Presentation).

Remaining release checks: force-kill during publication, storage exhaustion, long/mixed-codec projects, physical audible DSP/music/sync assessment, portrait rotation metadata and preview parity across supported devices. Current audio integration uses generated silence and proves pipeline execution, not perceptual audio quality. Release hardening must retain these as open gates rather than claim certification.
